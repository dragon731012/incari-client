# app-web runs tools:webbuild (the TeaVM compile), tools:shaders (the shader translation) and
# tools:sprites (the vanilla sprites decoded for the asset pack) as build tools; nothing of them
# ships. tools:shaders loads the game on the build machine's JVM to list its pipelines (ADR 0007),
# and tools:sprites to decode the sprites with the game's own code (ADR 0026). tools:wsbridge is a development WebSocket-to-TCP bridge for
# testing against a vanilla server (ADR 0009), standing in for an Eagler proxy (ADR 0016);
# tools:webbuild runs it in-process for the screenshot-diff harness (ADR 0012). :via is the Via
# stack under the game's pipeline (ADR 0017): Netty and the Via libraries, no game types.

# :framework is the module framework (ADR 0046): no game types. Each :features:<name> depends on it
# alone, never on another feature, the game or the platform; :client lists the features and adapts
# the game to the framework (incari.client.modules).

# tools:onlinedev serves :online's test fake over a real WebSocket, a stand-in for the online service
# while the client's account screens are tried; never shipped.
# :online is the client's side of Incari accounts and the online service (ADR 0058): the connection,
# the protocol and the world's Incari players, no game types; :client draws its screens.
